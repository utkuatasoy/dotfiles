# Skill: Conventional Commits (Efficiency-Aware)

Git commit conventions for this user. Follow these rules when creating commits.

---

## Commit Message Format

Single-line only, no body:

```
<type>(optional-scope): <imperative subject>
```

## Rules

- No emoji
- No multiline body or description
- No `Co-Authored-By` or any co-author attribution
- Keep under ~72 characters
- Imperative mood (add, fix, remove, refactor)
- No "generated by..." text

## Coding Efficiency (Critical)

**Formula:** `Efficiency = Added / (Added + Deleted)`

| Efficiency | Action |
|------------|--------|
| > 60% | Commit as-is |
| < 60% | Combine with productive changes |

**Key rules:**
- Never commit pure deletions alone (very low efficiency)
- Bundle deletions with their replacements
- Combine small chore/docs with the main feat/fix they support

## Types

| Type | Purpose |
|------|---------|
| `feat` | New feature |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `style` | Formatting only (no logic) |
| `refactor` | Code change without feat/fix |
| `perf` | Performance improvement |
| `test` | Tests only |
| `chore` | Tooling/config/housekeeping |
| `ci` | CI/CD related |

## Examples

Good efficiency:
- `feat: add user session timeout handling`
- `refactor: replace REST client with GraphQL` (deletion + addition together)
- `feat(auth): add OAuth2 and remove legacy auth`

Anti-patterns (avoid):
- ❌ `chore: remove unused imports` (pure deletion)
- ❌ `chore: delete deprecated files` (pure deletion)
- ✅ Instead: Include deletions with the replacement code

## Commit Grouping

**COMBINE** when:
- Deletion + replacement (avoid low efficiency)
- Small docs/chore + main feature they support
- Config removal + new config

**SPLIT** when:
- Unrelated features (each with efficiency > 60%)
- Very large changes (>25 files or >800 lines)

Use dominant type when combining: `feat` + small chore → `feat`

## Important

- Calculate efficiency: `git diff --numstat | awk '{add+=$1; del+=$2} END {print add/(add+del)*100}'`
- Never use `git add .` for large changesets
- Stage by path or hunk for controlled commits
- Review with `git diff --staged` before committing
